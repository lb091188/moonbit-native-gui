# mng commands & config

`mng` is the toolchain facade of native-gui: project scaffolding, `.mng` pages, the hot-reload loop, packaging & publishing, environment health checks, and the language server all enter here. Grammar in [Single-file components (.mng)](./sfc); hot reload and editor in [Hot reload & editor](./mng-dev); the publishing story in [Packaging & auto-update](./publish).

## Install

The tools ship with the repo; `moon install` works **per executable package** (a module path fails with "not a main package"):

```sh
moon install ./tools/native-gui-tools/mng      # CLI facade
moon install ./tools/native-gui-tools/mngui    # GUI wizard (launched by bare mng)
mng --version   # should print the mng version and mng-schema bit
```

The bare-`mng` state machine:

- `~/.mng/ready` absent (first run, or the version line mismatches after an upgrade) → runs one [health check](#mng-doctor) automatically; all green writes ready and continues; red items list fixes and exit.
- ready valid → launches the `mngui` wizard (looked up next to mng, then `~/.moon/bin`); if missing, an install hint is printed.
- No display service (SSH/CI) or wizard exit code 3 → falls back to usage.
- The gate applies only to the **argument-less interactive** entry; subcommands like `mng dev` and CI are never affected by ready.

## Command reference

| Command | Effect |
|---|---|
| `mng new <name>` | Generate a runnable minimal project (`new app <name>` explicit synonym) |
| `mng new page <path>` | Generate a single-page `.mng` sample (creates parent dirs) |
| `mng init` | Adopt templates in an existing project: write an `mng.toml` sample at module root (never overwrites) |
| `mng dev` | watch + hot reload + fallback orchestration (see [Hot reload & editor](./mng-dev)); `-h` for details |
| `mng build` | No args: generate **production-form** code for the whole project per `mng.toml`; `mng build <in.mng> -o <out.mbt>` compiles one file |
| `mng package` | Package platform-native app artifacts (see [Packaging & auto-update](./publish)); `-h` for details |
| `mng publish` | Scan `.mng/dist/`, generate update.json, upload a draft Release via gh |
| `mng doctor [-f]` | Environment health check; all green writes `~/.mng/ready`, `-f` forces a re-check |
| `mng lsp` | Language server (stdio JSON-RPC, the engine behind the VS Code extension) |
| `mng ir <in.mng>` | Print the template IR patch (for debugging the hot-reload channel) |
| `mng map-errors --map <map> <log>` | Map generated-code line:col in a `moon check` log back to template line:col |
| `mng gen <in.mng> -o <out.mbt>` | Dev-form compile of a single template (used internally by the dev loop) |

CLI messages and errors follow `LC_ALL` / `LC_MESSAGES` / `LANG` (a `zh` prefix selects Chinese); add `-h` to any subcommand for details.

## mng.toml

Generated by `mng init` / `mng new`; `mng dev` / `mng build` locate it upwards when run without args, falling back to defaults derived from `moon.mod` / `moon.work`.

### [dev]

| Key | Default | Meaning |
|---|---|---|
| `templates` | `["."]` | Directories scanned recursively for `*.mng` (relative to this file); skips `_build` / `.mooncakes` / dot dirs |
| `build` | `"moon build ."` | Build command |
| `run` | `""` | Launch command; empty = build once and grab the executable from the Artifacts output |
| `app-id` | `""` | Single-instance wake id; empty = derived from moon.mod's name (bare names get a `local.` namespace) |
| `poll-ms` | `300` | File polling interval (ms) |
| `theme` | — | Theme JSON path; saving the file hot-reloads it (no restart) |

### [package]

Packaging declaration (read by `mng package` at project root; builds for the host platform):

| Key | Default | Meaning |
|---|---|---|
| `id` | `""` | Reverse-DNS id: mac bundle id / artifact slug |
| `name` | `""` | Display name (.app / DMG volume / installer title) |
| `version` | `"0.1.0"` | App version, three numeric parts; independent of the moon.mod module version. **Change versions only here** — `mng dev/build/package` regenerate the `appmeta/` leaf package, the single source for the app's self-reported version |
| `bin` | `""` | Executable name; empty = grabbed from build artifacts |
| `icon` | `""` | Source icon, 1024×1024 PNG, derived to icns/ico (the wizard's icon step wires this) |
| `resources` | `[]` | Bundled resources (copied recursively into Contents/Resources / the install dir) |
| `maintainer` | `""` | deb control Maintainer (`"Name <email>"`) |

### [package.sign]

| Key | Meaning |
|---|---|
| `mac_identity` | codesign identity, e.g. `"Developer ID Application: NAME (TEAMID)"`; empty = adhoc |
| `notarize_profile` | notarytool keychain profile; non-empty enables notarization + staple |

## Generated-code discipline

- Generated code `<stem>.gen.mbt` lands next to the template with a `// GENERATED … DO NOT EDIT` header; **commit it** (consumers need no toolchain).
- Dev and production forms share the same file and overwrite each other — pick one before committing and stay consistent.
- CI checks freshness for both forms: a non-empty diff after regeneration fails the build (editing a template without regenerating gets caught).
- "Generated code out of date" → re-run `mng dev` (dev form) or `mng build` (production form), then commit.

## mng doctor

Probes moon / C & C++ compilers / (Linux) GTK dev packages (Python is an optional hint — the build now uses the MoonBit prebuild), then runs a **moon native build probe** (writes a minimal hello project under `~/.mng/doctor/probe/` and really builds it — the verdict is success/failure); on Windows the MSVC verdict is the probe itself (a vswhere hit only skips it). Optional items (WebView, media libs) warn without blocking.

- All green writes `~/.mng/ready` (an mng version line, re-checked on upgrade); `-f` forces a re-check.
- Fix hints lead with GUI links (official download pages first, package managers second); probe logs live in `~/.mng/doctor/`.
