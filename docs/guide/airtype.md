# airtype：手机扫码投字

airtype 是本仓的独立应用（`apps/airtype`）：电脑起一个局域网服务并显示二维码，手机扫码进网页打字，点发送后文字直接打进电脑当前聚焦的输入框——不用装输入法、不用聊天软件中转。

- 平台：macOS 先行；Linux X11 随后批次，Windows 不在本期。
- 同步进 `gui/sys` 的通用能力：[文本注入](../capability/sys.md#文本注入-inject)（把任意文本投进系统聚焦输入框），第三方应用可直接复用。

## 运行

```sh
moon run apps/airtype
```

窗口四张卡：

| 卡 | 内容 |
|---|---|
| 辅助功能授权 | mac 注入的前置权限状态与「去授权」按钮 |
| 二维码 | 手机相机扫码即打开输入页 |
| 服务状态 | 服务状态、局域网地址、已连接手机数 |
| 最近上屏 | 最近收到的文本预览 |

默认端口 8787，环境变量 `AIRTYPE_PORT` 覆盖：

```sh
AIRTYPE_PORT=9000 moon run apps/airtype
```

## 首次授权（mac）

上屏注入走系统合成键盘事件，macOS 要求「辅助功能」授权：

1. 点窗口里的「去授权」，系统弹引导框并打开设置页；
2. 在「隐私与安全性 → 辅助功能」里勾选本应用（裸 `moon run` 起的进程显示为终端应用，勾终端亦可）；
3. 回到窗口，两秒内状态自动刷成「已授权」。

未授权时手机仍可连接发送，但网页会收到「上屏失败」回执。

## 手机侧

扫码打开的页面只有一个输入框和发送按钮：输入 → 发送 → 文字出现在电脑聚焦的输入框，页面显示「已上屏」。断线自动重连；电脑重启应用后 token 已换，旧页面连不回，重新扫码即可。

## 安全边界

- 网址带一次性随机 token（32 字符）：同网段的陌生设备没有 token 拿不到页面，也连不上 WebSocket。
- 明文 HTTP：局域网内可见通信内容，不要在不可信网络使用；HTTPS 自签证书在手机端要手动信任，体验差，本期不做。
- 密码框不收注入：macOS 按系统设计不向密码框投合成事件，属预期行为。

## 已知边界

- 电脑与手机须在同一局域网，且电脑有 RFC1918 私网地址（10.x / 172.16~31.x / 192.168.x）；没有私网地址时显示「无网络」。
- 地址取物理网卡的私网地址——装了代理 TUN / fake-ip 的机器上 198.18.x 虚拟网卡地址不会被选中。
- 注入目标是**当前聚焦**的输入框——发之前确认电脑焦点在你想输入的地方。
