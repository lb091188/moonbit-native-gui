# native-gui 测试用例

> 九个示例应用 × 三平台（Linux / macOS / Windows），按「**应用 → 页面 → 段落**」组织，顺序与真机操作顺序一致：一个应用跑一遍就能连着测完，不用来回跳。每条只写本条的检查点，其他条目的内容不串进来。
> 编号与 `测试文档/index.html` 记录台一一对应（`HL` / `SC` / `BR` / `AU` / `VD` / `TP` / `SM`），网页里点通过的条目就是这里的条目；记录台加载本文件现算清单与条数，**本文件是用例的唯一事实源**。
> 共 211 条：Hello 11、Components 92、Canvas 12、System 21、Browser 23、Audio 14、Video 12、Theme Playground 7、Sysmonitor 19。

## 怎么用

1. 通过本地 HTTP 服务打开 `测试文档/index.html`（VS Code Live Server、`python3 -m http.server` 均可；file:// 双击会被浏览器拦掉用例读取，页面会给横幅提示），顶栏填当前 commit。
2. 选平台 → 选应用，按本文件的顺序逐段往下点：通过 / 失败 / 跳过。失败项在备注里写一句现象（读数、报错行、位置偏移量）。
3. 一个应用测完再换下一个；同一平台测完再换平台。三个平台的结果互相独立，网页里按「平台 + 应用」分开记。
4. 要交给 AI 修时，用执行页的「失败 → AI 提示词」，得到的是按测试环节分组的失败清单。
5. 没有示例入口的功能（字距 / 虚线 / 最大化）走**附录 D**：直接跑对应的 `moon test`，读数按那里的判据对。

勾选约定：本文件里的 `- [ ]` 是「本轮人工勾选」，与网页记录**择一即可**（网页记录更完整，能带 commit 与历史）。附录 D 不进网页记录，`moon test` 就是判定。

## 0. 公共前置

| 项 | 内容 |
|---|---|
| 构建 | 仓库根执行 `cd gui && moon check --deny-warn` 应为零错误零警告 |
| 启动 | 进示例目录执行 `cd examples/<名字> && moon run .`（每个示例目录是独立模块）；产物路径见 `docs/zh/build.md` §5「新增示例模块」 |
| 平台 | Linux（Ubuntu 24.04 + X11 + XFCE）、Windows（Win32 10/11）、macOS（Apple Silicon）三平台同一份清单，均已真机执行；平台差异记进备注与附录 A |

| 回报格式 | `编号 + 现象 + 截图（能截就截）+ 退出时读数行`，例：`SC-4.5 拖列边界不跟手；TABLE wins=1 cols=2` |

## 2. Components（`cd examples/components && moon run .`）

组件库演示板：侧栏 16 个页面，每页顶部还有一排**段**标签（segmented）。测法固定为：**点开一页 → 切到某段 → 段内逐项操作 → 下一段 → 下一页**。切换段只改可见性，各段滚动位置会各自保留。

> `SC-0.1` 是整板导航，先测它，后面每页都靠它跳转。

### 2.1 整板导航

| 编号 | 段落 | 检查点 | 操作 | 预期 |
|---|---|---|---|---|
| SC-0.1 | — | 十三页逐页切换 | 侧栏从上到下点完 13 项，中间穿插用页内段标签切段 | 标题与内容一一对应，无空白页、无上一页残留、无卡顿 |
| SC-0.2 | — | 全局观感（深浅两套） | 先看浅色，再点侧栏月亮切深色，再切回 | 侧栏是面板底、主区是页面底，两栏能一眼分开；卡片/面板四角是 6、控件 4，没有圆角大于 8 的元素；没有投影，层次全靠底色与 1px 描边；深色下文字与描边都还看得清（无写死浅色的地方） |
| SC-0.3 | — | 段条与段正文高度（任意多段页） | 打开基础组件页看段条下方；把窗口拉窄到段条折出第二行；段正文滚到底再切段回来 | 段条按实际行数占高、下方没有空白带；段正文视口恰好吃满「窗口 − 段条」并在段内自滚；折行后正文高度让足、段条不裁标签 |

## 附录 A 平台差异（不是 bug）

三平台（Linux / Windows / macOS）已按同一份清单在真机上跑过，下面是仍然存在的**平台差异**——属于系统约束或已声明的边界，不是缺陷。

| 现象 | 说明 |
|---|---|
| 通知在裸 `moon run` 下报「后端不可用」（macOS） | `NSUserNotification` 只认从 `.app` bundle 起的进程，裸二进制投递被系统静默丢弃。复验走 `moon build examples/components --target native && scripts/make_app.sh components` |
| 菜单栏出现在屏幕顶部而非窗口内（macOS） | 系统约定：菜单条属 App 不属于窗口，多窗时后挂的赢 |
| 全局热键只认 US 布局的物理键（macOS） | 走 Carbon 硬件键位，非 US 键盘同一物理键字符不同 |
| 无边框形态下窗口上没有系统最大化按钮 | 系统标题栏的三键（最小化 / 最大化 / 关闭）由装饰提供，`set_borderless` 之后装饰被去掉。自绘标题栏要自己放这个键，用 `set_maximized` / `is_maximized`（见 SC-10.1）；默认形态下按系统按钮即可最大化 |
| 播放器控制族（MPRIS）给 Unsupported（macOS / Windows） | 无对等物，属声明过的边界 |
| 无合成器时窗口透明度静默无效 | `set_opacity` 依赖合成器，无合成器不报错也不生效 |
| 单实例在没有会话总线的 Linux 上落 AF_UNIX 套接字档 | D-Bus 知名名声称失败（headless、无 dbus 的桌面）时门面顺延到套接字档，语义与 dbus 档一致（进程唯一 + 唤起已有实例），只是通道不同；读数见 SC-11.12 |
| macOS 崩掉的首实例在 `$TMPDIR` 留一个套接字残桩 | 下次启动先试连，连不上就撤掉残桩重新 bind 接管，不需要手工清；文件名带 uid，多用户共用 `/tmp` 时互不认领 |
| Windows 上唤起对方要对方在抽消息 | WM_COPYDATA 由同步投递送进首实例的消息队列，首实例卡在长任务里时第二实例最多等 3 秒后报「对方没在抽消息」，不会吊死 |

## 附录 C 界面基准（`native-gui-design` 技能，2026-10-21 统一后）
