怎么用

记录一条结果

选平台 → 选应用 → 按页面与段落逐条点「通过 / 失败 / 跳过」。状态即点即存，不需要额外保存动作；失败项请补一句备注（现象、读数、报错行）。

往下滚、平台与应用选择器划出屏幕后，顶部标签栏右侧会出现「当前平台 · 当前应用 + 进度」，点它一键回到顶部重新选。

为什么带 commit

每条结果都会记下顶栏的 commit 与当前时间。只有带上 commit，才能回答「这条是哪版挂的」。切换版本前记得改一下顶栏的 commit 字段。

历史从哪来

不需要手动开一轮测试。「历史」页按「平台 + 应用 + 日期 + commit」自动聚合，把同一天同一版本内的操作汇成一次测试，失败项单列。

把失败项交给 AI 修

三个入口都能一键把失败项拼成提示词并复制到剪贴板，直接粘给 AI 对话即可：

  • 执行页右上的「失败 → AI 提示词」：当前平台 + 当前应用的失败项。
  • 总览页右上的「全部失败项 → AI 提示词」：三个平台所有失败项，按平台 + 应用分段。
  • 历史页每张卡片上的「复制为 AI 提示词」：那一次测试的失败项。

格式保持简短：开头两行是平台与应用，然后按「测试环节」分组，逐条列「序号、条目」，下一行是「问题：你填的备注」（没写会标「（未填写）」）。

复制总体情况（更新路线图用）

总览页右上的「总体摘要」复制的是**整轮结果**，不是失败清单：表头写日期与 commit，第一行是「共 N 条：通过 / 失败 / 跳过 / 未测」，接着是一张「应用 × 平台」的通过率表，然后失败项按平台 → 应用 → 测试环节连续编号（1、2、3…），最后是未测项清单（按平台 + 应用列编号，超过 40 条截断）。

它不改路线图——用例按「页面段落」切、路线图按「功能点」切，两者不是一一对应。判一条路线图要不要从 🚧 变 ✅ 时看三样：该平台这一行有没有失败、相关用例是否都测过、未测清单里还剩什么。

快捷键

  • 1 通过 · 2 失败 · 3 跳过 · 0 清除
  • ↓ ↑ 在用例间移动；Enter 聚焦备注
  • ⌘Z / Ctrl+Z 撤销上一步

数据存在哪

本机浏览器的 localStorage（键名 ngtt.v1），不上传任何服务器，关掉页面不丢。它绑定「这台机器的这个浏览器」，换浏览器或清站点数据会丢——所以提供了「导出」：得到的 JSON 可以放进 测试文档/ 一起提交，需要时用「导入」合并回来（按时间取新、日志去重）。

页面被嵌在沙箱 iframe 里打开时（例如某些预览面板），浏览器会拒绝 localStorage，此时页面顶部会出现黄条提示，记录只留在内存。要正常保存，请用浏览器直接打开本文件。

用例库来源

按「应用 → 页面 → 段落」组织，编号与 测试文档/测试用例.md 一一对应：HL = Hello、SC = Showcase、BR = Browser、AU = Audio、VD = Video。条数与应用内计数在加载时从用例文档现算。改用例只改 测试用例.md，本页刷新即生效。

已知边界

  • 不存截图。失败项用文字备注，需要图就把文件名写进备注。
  • 只在一台机器上记录：其余平台用远程桌面 / 虚拟机操作时，用同一份页面切平台标签记录即可。
  • 浏览器禁用本地存储时（个别隐私模式），页面会提示写入失败，此时只能用导出备份。
