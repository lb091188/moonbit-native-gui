# 滚动横纹根治与帧节奏对齐

> **状态**：三批已合入（2026-11-24），真机复验待用户执行。
> **起因**：hello 示例真机滚动仍有横纹；流畅度不及同一台机器上的 Chrome。
> **本稿口径**：2026-11-24 重新调查后修订。结论全部来自本机可复现的无头测量，上一稿里立论实测不成立的一条改项已删除。

## 1. 调查结论

### 1.1 目标机器与目标口径

- 机器：Apple M4，10 核，16GB。
- 屏幕：外接 1920×1080，60Hz，缩放 1.0。
- 帧预算：16.7ms。
  - 大白话：屏幕每秒刷新 60 次，每次刷新之前要把下一帧画完，画不完这次刷新就没有新画面。
- 目标口径：每个刷新周期都有一帧新画面，每帧位移均匀，输入到上屏的延迟更低。
  - 上屏：把画好的一帧交给系统显示到屏幕上。
  - 这块屏每秒最多显示 60 帧。「比 Chrome 顺」指位移均匀度不低于 Chrome、延迟更低；帧数上限由屏幕决定。

### 1.2 横纹根因

- 根因：条带快路径平移上一帧时，把滚动视口自己画的 1px 描边那一行也当成了内容，搬进视口内部，此后不再重画。
  - 视口：滚动容器里看得见的那一块区域，内容在它里面上下移动。
  - 条带快路径：滚动帧的出画方式，把上一帧整体平移，只重画刚露出来的一窄条。
  - 描边：视口四周那圈 1 像素宽的边线。
- 成因过程：
  - 往下滚 3px：上一帧最底下一行是视口底边框，平移后落在第 676 行；新露条带只从第 677 行起盖，这一行从此留在视口里。
  - 往上滚 3px：上一帧最顶上一行是视口顶边框，平移后落在第 3 行。
  - 每滚一帧多一条，旧线条随内容一起走。所以横纹成片出现，整视口重绘清掉之后又重新长出来。
- 复现方法：无头环境里用带文字、带描边卡片的页面滚动，每一帧的条带结果与同一偏移的整幅重绘逐像素比对。
  - 无头：不开真窗口，在内存里出帧做比对。
  - 整幅重绘：不看上一帧，从页面底色开始把整窗重新画一遍，结果当基准。
- 证据，24 帧滚动序列：

| 场景 | 与基准不一致的像素总数 | 单帧最宽一行 |
| --- | --- | --- |
| 卡片页，视口 1px 描边，现状 | 4,828 | 751 像素 |
| 同上，重画范围多含 2 行 | 4 | 4 像素 |
| 同上，视口不带描边 | 4 | 4 像素 |

  - 现状下每帧恰好留一行，位置等于边框行加减本帧位移，颜色是描边色，正确值是页面底色。
  - 残余的 4 个像素是圆角卡片角落抗锯齿像素上 1–2/255 的舍入差，肉眼不可见。
  - 抗锯齿：图形边缘用半透明像素过渡，让斜边和圆角看起来不毛糙。
- 基准可靠性：同一偏移连续两次整幅重绘逐位一致，全帧不透明；两项自检都过才取读数。

### 1.3 流畅度瓶颈

| 瓶颈 | 现状 | 影响 |
| --- | --- | --- |
| 周期自愈帧 | 调试版整视口重绘 22ms；真机 `max_frame` 62–125ms | 约每秒 3 次卡顿，一次丢 4–7 个刷新周期 |
| 帧节奏 | 弹簧每 8ms 排一拍，不等屏幕刷新 | 帧与刷新不对齐，位移忽大忽小 |
| 文本重复绘制 | 每段文字每次绘制都新开离屏位图，重新排版并光栅化 | 整幅重绘贵；宽文字行页的条带帧也要 8ms |
| 条带帧固定开销 | 整窗快照加逐像素平移，发布版 2.2ms | 窗口越大越慢；2 倍屏落进慢路径 |

- 自愈帧：滚动中每 40 拍强插一帧整视口重绘，用来盖住横纹的补丁。
  - 它是拿流畅度换残影。根因修掉之后应整批撤除。
- 弹簧：让滚动有惯性滑行和触边回弹的动画算法。
- 离屏位图：先在一块临时画布上画好，再整块贴到窗口画面上。
- 光栅化：把文字轮廓变成一个个像素。
- 慢路径：平移时逐像素做坐标换算和颜色换算，比整块拷贝慢一个量级。

### 1.4 读数

- 采集方式：本机无头，hello 同规模页面，窗口 760×680，缩放 1.0，24 帧滚动序列取平均。
- 采集日期：2026-11-24。

| 页面 | 调试版条带帧 | 调试版整幅重绘 | 发布版条带帧 | 发布版整幅重绘 |
| --- | --- | --- | --- | --- |
| 卡片页 | 4.5ms | 22ms | 2.2ms | 7.9ms |
| 宽文字行页 | 11ms | 30ms | 8.0ms | 14.3ms |

- 宽文字行页：每行都是贯穿整宽的长文本。
  - 滚动条那一列和新露条带每帧各重画一遍，与之相交的宽文本行被整段重新排版、光栅化，哪怕只需要其中一条窄边。
- 真机 PROF：用户贴的读数出自调试版，滚动帧平均 8–18ms。
  - 流畅度评估一律用发布版。
- PROF：帧耗时账本，`NATIVEGUI_PROF=1` 时每 2 秒打一行。

### 1.5 与既有口径的出入

- 源码注释把横纹归因为亚像素残差累积，实测不成立。
  - 文字在离屏位图上按整数原点光栅化后整块贴回，整数平移下逐位一致，产生不了残差。
- 现有条带白盒用例测不出这条鬼线。
  - 一部分的场景里视口描边被不透明的行底色盖住，另一部分的视口根本没有描边。
  - 端到端用例只比终态，终态已被自愈帧整视口重绘覆盖。
- 无头测试宿主不铺页面底色。
  - `test_headless` 的根控件没有装页面底色绘制回调，底色是透明的。
  - 半透明边缘像素在透明底上每重画一次叠深一档，基准帧带着历史，比对不干净。
  - 新用例必须自己铺不透明页面底色，并带上 1.2 的两项自检。

### 1.6 实测排除的方向

- 剔除外扩 1px。上一稿认为描边有一半落在布局矩形之外，控件底边压在条带上沿时会被整条剔除。
  - 实测：矩形描边画在布局矩形内侧，框架不提供投影。构造「底边恰好压在条带上沿」的场景，16 帧只有 52 个 1/255 的像素差，没有任何成行差异。
  - 结论：不做。
- 上屏撕裂。
  - mac 纯光栅档的 `present` 只把帧拷进后备缓冲并请求重绘，真正贴像素在 AppKit 的下一次 `drawRect`，整帧贴出。
  - GPU 上屏档经交换链整帧呈现。
  - 两条路径都不撕裂，横纹与上屏无关。

## 2. 目标与判据

- 横纹：滚动中与停止后视口内无横纹。无头用例逐帧比对，任何一行差异像素不多于 4 个，任何像素单通道色差不到 3。
- 自愈帧：滚动期间不再出现整视口重绘帧。
- 每帧成本：mac 发布版卡片页条带帧 1ms 以内，整幅重绘 4ms 以内。
- 帧节奏：mac 发布版滚动期间每秒 58–60 帧，帧间隔 p95 不超过 17ms，超预算帧数为 0。
  - p95：95% 的帧间隔都不超过这个数。
- 门禁：三平台 `moon check` 零错误零警告，点名包 `moon test` 零失败。

## 3. 方案

三批各自独立可发，顺序固定：先修正确性，再降每帧成本，最后对齐刷新。

### 3.1 批次 A：横纹根治

- A1 重画范围盖住视口描边
  - 改 `gui/ui/scroll.mbt`：`scroll_view` 与 `virt_list` 建视口时把描边墨迹宽度记进 `ScrollState`，取描边宽度向上取整再加 1，无描边记 0。
  - 改 `gui/widget/app.mbt` 的 `paint_frame` 条带分支：新露条带的高度加上这项宽度；对侧补线的高度取 2 行与墨迹宽度中的较大值。
  - 墨迹：视口自己画的、不随内容滚动的像素，这里指那圈描边。
- A2 撤自愈帧
  - 改 `gui/ui/scroll.mbt`：删除每 40 拍的周期自愈帧与停止时的自愈帧，`tick_n` 字段一并删除。
  - 修正 `paint_frame` 与 `tick` 里把横纹归因为亚像素残差的注释。
- A3 回归守卫
  - `gui/widget/scroll_strip_wbtest.mbt` 新增用例：宿主根控件铺不透明页面底色，视口带 1px 描边，内容为圆角描边卡片，上下两个方向各 30 拍、位移 1–40 混合，逐帧与整幅重绘比对。
  - `gui/ui/scroll_wbtest.mbt` 新增用例：真实 `scroll_view` 加文字与按钮的同口径序列，外加工况「控件底边压在条带上沿」。
  - 夹具带两项自检：连续两次整幅重绘逐位一致，全帧不透明。
  - 既有两条「终态逐点一致」用例保持全等断言不动。
- A4 文档与台账
  - `experience/adaptation/common.md` 滚动动画一节：补横纹根因，补无头宿主不铺底色的口径。
  - `experience/design.md`「口径记录」新增下一条：条带快路径的精确性规则。
  - `测试文档/测试用例.md` 的 SC-0.6 判据改为「无横纹，不依赖自愈帧」。
  - 路线图条目移入「已实现」并按平台标状态。

### 3.2 批次 B：每帧成本

- B1 平移改就地逐行搬移
  - `gui/render/bitmap.mbt` 新增按行搬移方法：内容上移时自上而下，下移时自下而上，每行整块拷贝，不分配。
  - `paint_frame` 条带分支改用它，删除进程级快照缓冲。
  - 命中条件：视口矩形与位移在设备像素上都是整数；不满足时沿用现有快照贴回路径。
  - 2 倍屏从此走行搬移，不再落进慢路径。
- B2 账本改微秒并加帧间隔统计
  - `gui/win/stub.c` 三平台各增一个微秒单调时钟：mac 与 Linux 用 `clock_gettime`，Windows 用 `QueryPerformanceCounter`。
  - `gui/base/prof.mbt`：分段计时改微秒，新增帧间隔 p50、p95、最大值与超预算帧数。
  - 既有字段原样保留，旧读数脚本不受影响。
  - Windows 现有时钟读数只有毫秒精度，换新时钟的实测结论回写 `experience/adaptation/windows.md`。
- B3 文本绘制结果缓存
  - 范围：`gui/text` 的 `draw_box_raster` 通道，mac 与 Windows 都走这条；Linux 的 cairo 通道不动。
  - 键：文本、字体、字号、字重、字距、字色、盒宽、对齐、换行与省略开关、设备缩放。
  - 上限：默认 16MB，按像素总量做最近最少使用淘汰；环境变量 `NATIVEGUI_TEXT_CACHE_MB` 可调。
  - 约束一：文本基方向切换时随测量缓存一并清空。
  - 约束二：入缓存的离屏位图必须先冲刷待批文本；Windows 文本批持有位图裸指针。

### 3.3 批次 C：帧节奏对齐刷新

- C1 mac 刷新回调通道
  - `gui/win/stub.c` 的 mac 分支新增开启刷新回调、关闭刷新回调、读取刷新率三个接口，用 `CVDisplayLink`。
  - 回调线程只记下目标上屏时刻并唤醒主循环，不做任何绘制。
  - 有帧请求时才开启，请求清空即关闭，空闲零唤醒。
  - Windows 与 Linux 保持现有定时器驱动，本批不改。
  - 链接面实测结论回写 `experience/adaptation/mac.md`。
- C2 帧时钟
  - `gui/shell` 新增帧时钟：各动画登记「下一帧要被调用」，同一帧合并成一次调用。
  - 滚动弹簧与中央动画登记表改由帧时钟驱动，不再各排 8ms 与 16ms 定时器。
  - 样式过渡与关键帧动画仍走自己的定时器链，本批不并入。
  - 弹簧按目标上屏时刻取位置，不按开始绘制的时刻，少一帧延迟。
  - 无刷新回调的平台与无头测试自动回退定时器；无头测试的虚拟时基行为不变。
- C3 PROF 新增帧节奏行
  - 每秒帧数、错过的刷新次数、刷新率、帧间隔分位数。

## 5. 风险与边界

- 调试版整幅重绘仍超帧预算；流畅度评估一律用发布版。
- Windows 与 Linux 在 C 批之后仍是定时器驱动，节奏不如 mac 稳。
  - 后续升级路径不在本批：Windows 接 `DwmFlush`，Wayland 原生档接帧回调。
- 120Hz 屏的帧预算是 8.3ms；整幅重绘要等 B3 做完才进预算。
- 视口自绘里不随内容滚动、又超出描边宽度的墨迹仍会残影；约定这种墨迹宽度由视口记进 `ScrollState`。
- 伸出控件布局矩形的墨迹在裁剪重绘下一向会被剔除。这是脏矩形重绘的既有边界，不在本批。
  - 脏矩形重绘：只重画发生变化的那一小块区域。
- 未验证项：真机视觉，Windows 与 Linux 两条腿，`CVDisplayLink` 在现有链接面下的符号可用性。本稿读数全部来自本机无头环境。
