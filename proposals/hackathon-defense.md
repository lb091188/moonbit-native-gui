### 1 为什么做 · 2:00

- 缺位：MoonBit 能写 WebAssembly、命令行工具、后端，但没有桌面——写完的程序没有窗口可开。
- 三条既有路线都不合身：
  - Electron 族：一百多 MB 的运行时，界面本质是网页。
  - webview 壳：原生的位置退居能力层，主界面还是交给 web。
    - webview：嵌在原生窗口里渲染网页的浏览器组件。
  - 绑定 Qt / GTK：语言只是 C 库的一层皮，不是 MoonBit 化。
- 判断：桌面 GUI 是语言生态成熟度的试金石，也是最难啃的一块；把它啃下来，MoonBit 能不能造大东西就有答案。
- 定位三词收束：原生自绘、全栈 MoonBit、web 级 DX。
  - 自绘：控件外观由框架自己画，不借用系统现成控件。
  - DX：开发者体验，开发顺手不顺手。

### 2 做成了什么 · 2:30，含演示到 4:30

三个系统性证据，不念功能清单：

- 证据一 · 三平台一条链：
  - 一份代码 Windows / macOS / Linux CI 全绿。
  - 1684 个库测试用例 + 199 条真机用例。
  - 0.3.3 已发 mooncakes，`moon add` 后零配置 `moon run`。
- 证据二 · 全栈纵深：
  - 自绘渲染引擎不依赖 Skia、Qt。
    - Skia：Google 的开源 2D 绘图引擎，Chrome 用的就是它。
  - 向上：30+ 组件族、19 种图表、Markdown 与代码视图。
  - 系统能力：托盘、通知、输入法、无障碍桥，三平台各接各的原生通道。
  - 纵深末端：媒体播放、WebView、GPU 合成、三平台打包与自动更新。
- 证据三 · 场景验证：
  - hello 二进制 mac 2.9MB，Electron 同类空壳百 MB 级。
  - moon-launcher 启动器跨三平台、中文拼音输入法原生。
    - 证据用途一句话带过，不展开产品叙事。

【演示插位】讲完证据一直接跑 hello，见「演示预案」。

### 3 为什么能做出来 · 3:30，重头戏

先立问题：AI 写大工程的通病——改 A 坏 B、幻觉接口、无法回归。

三个工程装置让 AI 产出可信：

- 装置一 · 编译器门禁：`moon check` 零错误零警告是唯一真值。
  - AI 说完成不算，门禁说了算。
- 装置二 · 无头测试：GUI 逻辑不开窗也能断言，确定性时钟可复现。
  - 无头：不开窗口、纯后台跑，供自动化测试用。
  - 1684 个用例 AI 自己红自己绿，不靠人眼。
- 装置三 · 人机分工：AI 管代码、测试、文档、提交；人管规划、真机验证、审美拍板。
  - 真机清单制度：AI 给操作步骤，人执行回填结论。

MoonBit 语言红利——语言本身对 AI 协作友好：

- 强类型 + 显式错误处理：AI 产出可预测，编译错误可执行，AI 能自纠。
- 无宏魔法：读码即真相，AI 与人看到的同一份代码。
- 单一构建工具 moon：门禁一条命令，AI 的验收闭环短。

产能读数：9 月 517 个提交，10 月 1106 个——人机磨合后产能翻倍。

### 4 工具链 DX · 1:30

- mng 一条命令全流程：
  - `new` 脚手架起工程 → `dev` 盯全工作区改码即起 → `lsp` 类型错误回投编辑器 → `inspector` 看控件树改样式 → `package` 三平台安装包 → `publish` 自动更新链。
  - mng：本仓的开发者工具命令行。
- Vue 风单文件模板编译成 MoonBit，报错经 source map 回映射到模板行列——DX 生死线。
  - source map：源码与生成码的位置对照表，让报错定位回你写的文件。
- inspector 还能经 MCP 给 AI 用：AI 起应用、看树、截图、自检界面。
  - MCP：AI 调外部工具的标准协议。
- 演示彩排时确认 hello 的 `mng dev` 实况后再定口径。

## 演示预案

首选 hello + sysmonitor 两个示例，操作由用户彩排执行：

- hello，约 60 秒：
  1. `cd examples/hello && moon run --target native`，零配置起窗。
  2. 点三档预设子窗按钮：备忘 / 调色 / 关于，开窗关窗。
  3. 指托盘图标：左键计数唤回，右键菜单退出。
  4. 时间富余才加：现场改 hello.mng 一处文案保存，看自动重编译重开窗。
- sysmonitor，约 45 秒：
  1. 起 `examples/sysmonitor`。
  2. 左栏切总览 / 进程 / 传感器页，指 CPU 各核小图与进程表。
  3. 一句话：这一屏用到了图表、表格、虚拟滚动、系统能力四层。
- 录屏兜底：
  - 两段各录一份，投影 1080p 分辨率。
  - 现场构建超时或拉包失败即切录屏。
- 风险点：
  - 演示机需预热 mooncakes 缓存，现场不走网络拉包。
  - 投影 DPI 与演示机分辨率不一致时窗口可能偏小，彩排时核。
  - 现场改模板的演示依赖 `mng dev` 当前实况，彩排确认后才进流程。

## Q&A 预案

按被问概率分五组。每题给回答要点与事实出处。

### 组 A · MoonBit 与语言，评委是官方，必问

**A1 为什么选 MoonBit 做这件事？**

- 要点：想在 WebAssembly 之外验证 native 大工程；语言现代——类型系统、显式错误处理、语法上手快；工具链迭代快、社区沟通顺。
- 出处：仓库首提交即选型后的产物，README 定位。

**A2 用 MoonBit 做这个最痛的点是什么？想向官方要什么？**

- 要点：三条上游诉求已立项——native 热重载、运行时多模块、native 增量链接；工具链快速演进期有 API 破坏需要跟版。
- 话术：这条是送给官方的反馈，roadmap 有记录，落地当天模板热更会从「编译重启」升格「真热换」。
- 出处：roadmap「已规划 · 开发体验 · 上游诉求」。

**A3 MoonBit 相比 Rust 做这件事的优势？**

- 要点：编译快、门禁跑得快——AI 自纠循环才快，这对本项目的协作方法关键；无生命周期标注的心智负担；FFI 直调 C，写绑定成本低。
- 出处：`gui/` 13.4 万行的迭代速度本身是证据。

**A4 moonbit 1.0 对项目意味着什么？**

- 要点：稳定面清单与 1.0 时点已规划——在 moonbit 1.0 之后评估；0.x 阶段破坏性改动靠提交信息与文档同步管理。

### 组 B · 架构与选型

**B1 为什么自绘而不是封装原生控件？**

- 要点：跨平台一致观感、主题化自由、三平台一套测试面；「原生控件皮肤」路线已明确不做；系统能力仍走各平台原生通道，两不误。
- 出处：roadmap「明确不做」。

**B2 FFI 的内存安全怎么保证？**

- 要点：绑定走 moonbit.h 桩加所有权注解；绑定规范沉淀成了可复用的方法论文档；原生桩语法门禁进 CI。
- 出处：`.agents/skills/moonbit-c-binding/`、ci.yml gate。

**B3 GPU 为什么是可选档而不是默认？**

- 要点：定位可选后端——构建级下载失败即降级、运行级探测回退 Cairo 或纯光栅；无 GPU 环境保底；逐像素透明档不走 GPU。
- 出处：roadmap「渲染与绘制 · GPU 合成」。

**B4 Linux 为什么基于 GTK3？**

- 要点：低版本发行版兼容的保障，工具包升级明确不做；Wayland 有限支持是协议限制，出路已按调研收口。
- 出处：roadmap「Linux 兼容说明」「明确不做」。

**B5 性能读数？**

- 要点：帧成本探针——mac 0.8ms、Linux 容器 2ms、win10 虚拟机 27ms 全窗帧；小脏区三平台全低于 0.5ms；内存线性上涨两例已修。
- 出处：roadmap「CPU 视觉能力批 · 成本读数」、近两周提交。

**B6 体积怎么控？**

- 要点：size-gate 工作流三平台量可执行字节数，增量超上限拦红；hello mac 2.9MB。
- 出处：size-gate.yml、tools/size-baseline.json。

### 组 C · AI 协作，自己点名的重点，必被问

**C1 AI 写了多少比例？这些代码你真的都懂吗？★ 最尖锐，必须备熟**

- 话术分层，先诚实后反守为攻：
  - 架构与关键路径——渲染管线、布局引擎、平台适配层——设计与验收我自己持有一手。
  - 面广量大的组件层，靠门禁、1684 用例、199 条真机清单兜底。
  - 「懂」的定义是能定位、能改、能验收，这个闭环我是持有人。
- 反攻点：这正是方法论的价值——门禁与测试让「不必逐行背下 20 万行」也能安全持有 20 万行；工业界靠类型和测试持有大代码库，AI 时代同理，只是杠杆更长。

**C2 怎么保证 AI 代码质量？**

- 三件套：`moon check` 零警告门禁、1684 库测试、三平台 CI 加本地五腿脚本对齐远端；真机 199 条用例人审。
- 出处：AGENTS.md 门禁清单、scripts/local_ci.sh。

**C3 协作工作流具体怎么搭的？**

- 要点：AGENTS.md 行为规则——规划后执行、一个功能一次提交、文档先行；文档站构建时聚合 llms.txt 给 AI 离线全集；mng lsp 让 AI 在编辑器回环里拿到真实类型错误。
- 出处：AGENTS.md、docs 构建、roadmap「mngdev 库包与工具链联动」。

**C4 真机测试 AI 做不了，怎么分工？**

- 要点：三档分工定案——无头断言归 CI、真窗冒烟归 xvfb、真机清单归人。
  - xvfb：Linux 上的虚拟显示服务，不开真屏也能起窗口跑冒烟。
- 出处：roadmap「无头化收尾 · 三档分工」。

**C5 这套方法别人能复制吗？**

- 要点：仓库本身就是样板——AGENTS.md、测试文档体系、门禁脚本全部开源；方法论写成了规则与工具，不是口头经验。

### 组 D · 完成度与可持续

**D1 一个人加 AI，之后可持续吗？**

- 要点：门禁与测试资产本身就是维护杠杆，回归成本低；roadmap 按已规划已实现流转，AI 靠它续上下文，接手者同理；文档站与示例降低社区进入门槛。

**D2 GUI 这么东西怎么测？**

- 要点：三档分工；确定性测试时钟——两会话同推程同读数；uitest 门面观察点没跑即红；199 条真机用例配记录台。
- 出处：roadmap「工程与交付」。

**D3 已知短板是什么？**

- 诚实清单提前备好，被问直接给：
  - Wayland 功能子集，X11 完整。
  - 媒体硬解 Linux 已通，mac 与 Windows 未接。
  - 无障碍的文档视图语义挂载有缺口。
  - 模板亚秒热更未到，当前是改码重编译重启。
  - Windows GPU 档尺寸变化回退 CPU 路径，上游库 bug 绕行。
- 话术：短板全部记录在 roadmap 与经验文档——「诚实降级」是本仓工程原则，探针不报假成功。
- 出处：roadmap 各 🚧 条目。

**D4 对比 Electron、Tauri、Slint、egui？**

- 一句话各定位：Electron 与 Tauri 是 web 主面，本仓是原生主面；Slint 与 egui 是 Rust 生态同类位，MoonBit 生态此前没有对位物——这正是做它的原因。
