# 方向:差距分析与补齐

2026-11-08 立档。对标对象 [egoist/mygo](https://github.com/egoist/mygo) v0.8.3,实测于当日克隆全仓 52 万行 Go、`ui/` 17 万行。本文档只做差距盘点与建议,**不改变任何既有定案**;确认立项的方向按流转规则进 roadmap「已规划」→ TODO.md 再动手。
  - mygo: Go 桌面应用框架,5.2k 星,2026-09-26 创建,零 cgo,立即模式 View 函数,GPU 自绘 + 系统 webview 双模态。
  - cgo: Go 调 C 代码的桥,零 cgo 即不依赖 C 侧胶水。
  - 立即模式: 每帧重画整个界面、不保留控件树的 UI 写法,配合编译快、重启快。
  - GPU 自绘: 界面像素由库自己用显卡画,不依赖系统原生控件。
  - webview: 系统内嵌的浏览器控件,可承载网页界面。

## A 类:实缺口逐项

### A1 应用打包管线·用户已确认·P0

- **现状**:release-bin 工作流出三平台 zip,属示例级;无 .app / 安装器 / desktop entry;体验文档让用户下载 zip 手动解压运行。
  - desktop entry: Linux 桌面登记应用的入口文件,应用能否进菜单、显图标、被文件关联都靠它。
- **mygo 做法**:一条 `mygo build` 出全平台产物——macOS `.app` + DMG、Windows NSIS 安装器、Linux deb / PKGBUILD / install.sh,另有 `install.ps1` 一行安装。
  - DMG: mac 的磁盘映像安装包,双击打开拖装。
  - hdiutil: mac 自带的磁盘映像命令行工具,mygo 用它制 DMG 并自生成 .DS_Store,不依赖 create-dmg。
  - NSIS: Windows 开源安装器制作系统,per-user 装到 `%LOCALAPPDATA%\Programs`,缺 makensis 时自动下载。
  - makensis: NSIS 的编译器,把安装脚本编成安装器。
  - per-user: 装进当前用户自己的目录,不需要管理员权限。
  - deb: Debian/Ubuntu 系软件包格式,mygo 用纯脚本 tar+control+md5 生成。
  - PKGBUILD: Arch Linux 的包构建脚本。
  - install.ps1: PowerShell 一键安装脚本。
  - irm|iex: PowerShell 的「下载命令管道接执行命令」,一句完成下载并运行。
  - SHA256: 对文件算固定长度指纹,内容差一个字节指纹就变,用来校验下载完整。
- **MoonBit 落地形态**:`mng build` 已存在,现职责为模板生产形态;扩 `--release` / `mng package` 子命令:
  - mac:`Contents/{MacOS,Resources,Info.plist}` 层级 + hdiutil 出 DMG;codesign ad-hoc 起步,Developer ID 与公证后置;
    - ad-hoc 签名: 不挂开发者身份的最简 mac 代码签名,只证包未被改动。
    - Developer ID: Apple 发给开发者的签名身份,配合公证才不会被 Gatekeeper 拦。
    - Gatekeeper: macOS 对下载来源应用的安全审查机制,未签名未公证会被拦。
    - 公证: 把应用提交 Apple 服务器扫描,通过后系统才放行外来应用。
    - 理由: 证书是用户资产,架构留口不阻塞。
  - win:NSIS 安装器,探测 makensis、缺失自动下载,同 mygo/Tauri 套路;per-user 装法为 A2 自动更新铺路;`.ico` 多尺寸生成;
    - Tauri: 主流开源桌面框架之一,此处指其安装与更新做法可参照。
    - 理由: per-user 目录用户可写,更新器替换文件无需管理员权限。
  - linux:deb 包用 control+md5+desktop entry 纯脚本可做、PKGBUILD 模板、tar.gz;desktop entry 图标与 mime 关联喂 A3;
    - mime: 文件类型标识字符串,如 `image/png`,系统靠它决定这类文件用哪个应用打开。
  - 资源随包:ffmpeg dll/dylib 随包已有先例,video 示例走 release 分发。
- **依赖**:`mng` 工具链与三平台 CI 矩阵均已有。**验收口径**:CI 只保构建通过;安装/卸载/升级观感走真机清单,归用户、符合现行规则。
  - CI 矩阵: 一条 CI 流水线配置成在 mac、Windows、Linux 各跑一遍的方式。

### A2 自动更新·用户已确认·P0·依赖 A1

- **mygo 做法**:Ed25519 签名清单 `update-<target>.json` + 自实现 bsdiff 增量 + 原子替换 + relaunch + native UI 更新窗口;更新源 feed 支持 GitHub Releases / S3;`-upload` 直发 draft release。
  - Ed25519: 一种现代签名算法,私钥签名、公钥验真伪。
  - bsdiff: 一种二进制差分算法,只算新旧版本差异、把差量当补丁下发。
  - 原子替换: 替换要么整体完成要么不动,不会出现半新半旧的中间态。
  - relaunch: 更新装好后自动重启应用自身。
  - S3: Amazon 的对象存储服务,这里指可挂更新包的云存储。
  - draft release: GitHub 上未对外可见的草稿发布页,先传产物、确认后再正式发。
- **MoonBit 落地形态·建议两期**:
  - **v1 全量**:检查: pr_run curl 拉清单 JSON → 下载临时目录 → 校验: SHA256、HTTPS 起步 → 原子替换: posix rename;Windows 运行中 exe 走 rename swap,旧改名 + 新落位 + 重启 → relaunch。更新窗口 UI 用本库 widget 画——「吃自己狗粮」的展示位,mygo 同款思路。
    - pr_run: 本库 `gui/sys` 的统一子进程封装,库内起外部命令都走它。
    - posix rename: POSIX 标准的原子改名调用,改名瞬间生效,用作替换手段。
    - rename swap: 运行中的 Windows exe 不能直接覆盖,先把旧文件改名让位、新文件顶上原名的替换手法。
  - **v1.5 签名**:Ed25519 验签;mooncakes 依赖待盘点,见文末;无现成绑定则 C 桩走 openssl。
    - mooncakes: MoonBit 社区包仓库,找现成依赖先查它。
    - C 桩: 手写小段 C 代码把库能力桥接进 MoonBit 的补丁层。
    - openssl: 最常用的开源密码学库,签名验签能力现成。
  - **v2 增量**:发布侧 diff 可先用系统 bsdiff 或自定 zstd/gzip 差分格式,不必复刻 bsdiff 的 bzip2 压缩口径;应用侧 patch 应用自实现,量级百行。
    - diff/patch: diff 算出新旧文件的差量,patch 把差量套回旧文件得到新文件。
    - zstd/gzip: 两种常见压缩格式,自定差分格式可借用作容器。
  - **分工**:检查/下载/替换/重启是库能力,收 `gui/sys`/`gui/win` 一侧的 update 门面;清单生成与上传是 `mng publish` 工具侧。
- **风险**:Windows 文件占用语义、mac .app 整包替换的 quarantine/translocate 属性、Gatekeeper 与公证的联动——真机清单项,后置批覆盖。
  - quarantine: macOS 给网络下载文件打的隔离属性,首次打开会弹确认。
  - translocate: macOS 对带隔离属性的应用搬到临时路径再运行的行为,可能干扰整包替换。

### A3 桌面登记面·与 A1 安装器耦合·紧随其后

- **现状**:无深链注册、无文件关联、无 jumplist、最近文件只有读侧。
  - 深链 deeplink: 从浏览器或其他应用经自定义网址协议直接唤起本应用。
  - 文件关联: 系统里登记「某扩展名的文件双击就用本应用打开」。
  - jumplist: Windows 任务栏右键菜单里应用专属的快捷项列表。
  - 读侧: 只能读出最近打开过什么,还不能把新打开的登记进系统。
- **mygo 做法**:deeplink 做自定义 scheme 注册 + 事件回调;文件关联走 Info.plist CFBundleDocumentTypes / Windows 注册表 / desktop entry mime;jumplist;最近文档写侧登记;开机自启,本库已有。
  - scheme: 网址协议名,如 `myapp://`,deeplink 的注册载体。
  - Info.plist: mac 应用包内的配置清单文件。
  - CFBundleDocumentTypes: Info.plist 里声明本应用可打开哪些文件类型的键。
  - 注册表: Windows 的系统级配置数据库,文件关联等登记处。
- **落地形态**:登记声明进 `mng.toml`,含 scheme 与扩展名列表,打包器落到各平台清单;应用侧事件回调,深链唤起走已有单实例通道转发 argv/URL。
  - argv/URL: 命令行参数与网址,即系统转给应用的本次打开请求内容。
  - 单实例通道: 二次启动不另开进程、把请求转交已运行实例的机制。

### A5 体积纪律与性能对比公开·P1·CI 侧便宜

### A6 CPU/GPU 像素对拍·P2·随 GPU 控件批

- **mygo 做法**:glass 效果三份 shader + 一份 CPU 光栅孪生,测试逐像素对拍,GPU/CPU 一致是验收线。
  - shader: 在 GPU 上跑的绘制小程序。
  - 孪生: 同一效果另写一份 CPU 逐像素实现,GPU 与 CPU 结果应一致。
  - 对拍: 两套实现喂同样输入、逐像素比对输出找差异。
- **本库地基**:GpuCanvas 离屏 finish 读回 BGRA 已通,三平台真机过;roadmap「无头像素快照基线」已规划,独立立项。
  - 离屏: 渲染到内存缓冲而非直接上屏,便于读回像素。
  - BGRA: 一种像素字节序,蓝、绿、红、透明四通道各一字节。
- **落地形态**:同一套比对器两用——快照基线管「跨版本不漂」,对拍管「GPU 路径与纯光栅逐像素一致」;随控件级 GPU 批扩用例模板。

### A7 确定性测试时钟·P1·最便宜先做

  - 确定性时钟: 测试里时间不跟真实墙钟走、由测试代码手动拨,同一用例每次结果一致。

## B 类:路线校准建议·最终归用户

### B1 模板与热更——方向继续,冻结的只是「HOT 覆盖面」

结论先行:模板与热更**继续做,不是砍**;建议冻结的只有一件事——HOT 覆盖面的继续扩张。
  - HOT: 热更,应用不重启就把改动套到运行中的界面。
  - COLD: 冷路径,热更吃不掉的改动走重启恢复、自动回到改动页。

- **为什么方向继续**:「让原生 DX 与 web 持平」是 2026-11-02 定的主战略,模板 + 热更是本库相对 mygo 的差异化卖点,不是追赶项——mygo 不需要热更是因为立即模式 + Go 秒级编译重启就够快;本库是 retained 树 + MoonBit,改模板重启要丢状态、回首页,热更的「亚秒 + 状态保活」是真价值,例:stepper 调到 7 走 HOT 后仍是 7。模板 DX 的非热更部分,即编译器、v-for、LSP、VSIX、mng new/build/dev,纯增益,照常推进。
  - DX: 开发体验,指写代码顺不顺手。
  - retained: 保留控件树、按需重绘的 UI 写法,与立即模式相对,是热更保状态的前提。
  - 状态保活: 热更后输入值、页码等界面状态不丢。
  - v-for: 模板里循环生成一列内容的写法。
  - LSP: 语言服务器协议,编辑器补全、跳转靠它。
  - VSIX: VS Code 扩展的安装包格式。
- **为什么冻结 HOT 扩面,三条**:①成本曲线陡——热更每多覆盖一档形态,applier 复杂度上一档,状态保活、IR rev 握手、回退编排都是为此付的,v-for 含热更一律转冷已是系统在自我保护,线已到头;②上游依赖——script/真代码热换要状态迁移快照 + 运行时换码,单独立项做不完,等上游 native hot reload,roadmap「上游诉求」已列,落地后整条链降级成真代码热换、COLD 回退自动消亡,现在扩面是给将来拆的路基加荷载;③回退已是正确形态——COLD 重启自动回改动页体验已闭环,HOT 再扩一档的边际收益小于 A 类实缺口。
  - applier: 把模板改动套到运行界面的执行器。
  - IR rev 握手: 热更两侧对齐中间表示 IR 的版本号,对不上即回退。
- **冻结线·现状即线**:HOT = 结构 / class / 样式值 / 受限表达式,含字面量、Store、运算、if、`tx`·`tr`、插值;COLD = script / v-for / 自定义组件 / children 形 / 文法外表达式。上游落地前不再把 COLD 项搬进 HOT;省下的精力转 A 类。

### B2 GPU 终态——L2 落地前先定「显示列表化」终态图

- **现状**:L1 是位图上传 + 全屏 quad,纹理合成,不是 GPU 绘制;wgpu 统一三平台,但 GTK 集成代价已实证,合成覆盖 → 自开 X 子窗承载。
  - quad: GPU 上的矩形面片,全屏 quad 即一张铺满窗口的纹理。
  - 纹理合成: 把 CPU 画好的整幅位图当贴图贴上屏,不是 GPU 逐条绘制。
  - wgpu: Rust 生态的跨平台 GPU 抽象库。
  - GTK: Linux 主流桌面图形工具包,本库在 Linux 借它开窗。
  - X 子窗: 在 X11 显示协议下另开的窗口,用来承载 GPU 画面。
- **mygo 参照**:显示列表,scene Op 流 + 每操作一个 instanced quad + 平台原生管线 Metal / D3D11 / GL,Linux 用 GtkGLArea 绕开 GTK 合成问题。
  - 显示列表: 把绘制动作记成一串指令、统一提交 GPU 执行的绘制方式。
  - instanced quad: GPU 实例化绘制,一份矩形几何批量复制画千百个元素。
  - Metal / D3D11 / GL: mac、Windows、跨平台各自的主流 GPU 编程接口。
  - GtkGLArea: GTK 内嵌的 OpenGL 画布控件。
- **校准点**:L2 GpuSink 协议已落,但「paint 产 Op 流 → quad 实例」的显示列表终态图未定;若不定,L1 位图上传有永居风险。wgpu 统一 vs Linux 腿 GL 直连值得在 L2 设计时再评估一次,GtkGLArea 是 mygo 验证过的路径——不是现在改,是 L2 动手前定图。A6 对拍是这条线的验收基础设施。

### B3 测试可信度模型——无头加厚,真机瘦身

- **现状**:规则「真机归用户」,159 条用例清单 + 记录台;无头门禁是 moon test 指定包。
- **mygo 参照**:730 个测试文件 16.3 万行,headless Tester 做内存渲染 + 假剪贴板/IME/拖拽 + 静止时钟,另有 e2e 走 Xvfb / 桌面会话,视觉与交互大量自动化,真机只验「必须真机的」。
  - headless Tester: 无头测试器,不开真窗口、在内存里渲染来跑断言。
  - e2e: 端到端测试,把整个应用从头跑到尾。
  - Xvfb: Linux 上带虚拟屏幕的 X 服务,没有显示器也能跑 GUI 测试。
  - IME: 输入法框架,中文等文字输入靠它进应用。
- **建议动作**:**不改规则**——加厚无头,即 A7 时钟 + A6 对拍 + uitest 扩面,把「布局/动画/绘制正确性」类用例沉进无头门禁,真机清单聚焦 IME / 托盘 / 通知 / 合成器 / DPI / 装机面这类真要真机的;长期看真机清单条数应下降而非增长,记录台压力随之减。
  - 托盘: 系统任务栏/菜单栏角落的应用图标区。
  - 合成器: Linux 桌面负责把各窗口拼到屏幕上的系统服务。
  - DPI: 屏幕像素密度,决定界面缩放倍率。

## C 类:已对齐 / 反超清单·防重复立项

- **窗口层选型**:AppKit / Win32 / GTK3 三平台同款,mygo 同款;它 zero-cgo 靠 purego,本库编译期 C 桩,是语言生态差异不是能力差异。
  - AppKit / Win32 / GTK3: mac、Windows、Linux 各自的原生窗口编程接口。
  - purego: Go 不经 cgo 直接调 C 的第三方库。
- **无障碍**:三桥同款,mac NSAccessibility / win UIA / linux AT-SPI,且「帧尾语义快照」与 mygo「每帧 AccessTree」设计撞车——两边独立收敛到同一形态。
  - 无障碍: 让读屏软件等辅助工具能理解与操作界面的能力。
  - NSAccessibility / UIA / AT-SPI: mac、Windows、Linux 各自的无障碍接口,读屏软件靠它念出界面。
- **IME**:TSF / NSTextInputClient / ibus+fcitx 通道一致。
  - TSF / NSTextInputClient / ibus+fcitx: Windows、mac、Linux 各自的输入法接入通道。
- **系统工具箱广度**:传感器/蓝牙/磁盘/浏览器历史/壁纸/电源计划/夜间色温 mygo 没有,本库反超。
- **媒体**:ffmpeg 全能,软解+硬解线,vs mygo 系统解码器 AVFoundation/MF/GStreamer 走零拷贝——取舍不同;硬解线落地后能力面等价,系统解码器路线可作为体积优化备选记档,与 media-decode-vendor 白名单线互补。
  - 软解/硬解: 软解用 CPU 解码视频,硬解用显卡解码、省 CPU。
  - 零拷贝: 解码出的画面不复制内存直接送显。
  - AVFoundation / MF / GStreamer: mac、Windows、Linux 各自的系统媒体解码框架。
- **编辑器/终端/图表/markdown/i18n/虚拟滚动/单实例/贡献入口**:完成度同档或反超,不立项。
  - 范围: 贡献入口指 issue/PR 模板与双语站。
