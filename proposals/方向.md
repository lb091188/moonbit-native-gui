# 方向:差距分析与补齐

2026-11-08 立档。对标对象 [egoist/mygo](https://github.com/egoist/mygo) v0.8.3(Go 桌面应用框架,5.2k 星,2026-09-26 创建,零 cgo,立即模式 View 函数,GPU 自绘 + 系统 webview 双模态),实测于当日克隆全仓(52 万行 Go,`ui/` 17 万行)。本文档只做差距盘点与建议,**不改变任何既有定案**;确认立项的方向按流转规则进 roadmap「已规划」→ TODO.md 再动手。

## 结论速览

- **A 类·实缺口(建议补)**:A1 应用打包管线、A2 自动更新、A3 桌面登记面、A4 内建 inspector、A5 体积纪律与性能对比公开、A6 CPU/GPU 像素对拍、A7 确定性测试时钟、A8 文档 AI 消费面、A9 窗口状态记忆与会话恢复。其中 A1/A2 用户已确认要做(2026-11-08)。
- **B 类·路线校准(不转向,调投入)**:B1 模板与热更方向继续、只冻结 HOT 覆盖面扩张、B2 GPU 终态先定「显示列表化」图、B3 测试可信度模型向无头加厚。
- **C 类·已对齐/反超(不立项,防重复)**:窗口层选型、无障碍三桥、IME 三通道、系统工具箱广度、媒体、编辑器/终端、图表、markdown、i18n、虚拟滚动、单实例、贡献入口。脏活完成度与 mygo 同一档次,部分反超。

## A 类:实缺口逐项

### A1 应用打包管线(用户已确认;P0)

- **现状**:release-bin 工作流出三平台 zip(示例级);无 .app / 安装器 / desktop entry;体验文档让用户下载 zip 手动解压运行。
- **mygo 做法**:一条 `mygo build` 出全平台产物——macOS `.app` + DMG(hdiutil + 自生成 .DS_Store,不依赖 create-dmg)、Windows NSIS 安装器(per-user 装到 `%LOCALAPPDATA%\Programs`,缺 makensis 自动下载)、Linux deb(纯脚本 tar+control+md5)/ PKGBUILD / install.sh,另有 `install.ps1` 一行安装(irm|iex + SHA256 校验)。
- **MoonBit 落地形态**:`mng build` 已存在(模板生产形态),扩 `--release` / `mng package` 子命令:
  - mac:`Contents/{MacOS,Resources,Info.plist}` 层级 + hdiutil 出 DMG;codesign ad-hoc 起步,Developer ID 与公证后置(证书是用户资产,架构留口不阻塞);
  - win:NSIS(探测 makensis,缺失自动下载,同 mygo/Tauri 套路);per-user 装法为 A2 自动更新铺路(可写目录);`.ico` 多尺寸生成;
  - linux:deb(control+md5+desktop entry 纯脚本可做)、PKGBUILD 模板、tar.gz;desktop entry 图标与 mime 关联喂 A3;
  - 资源随包:ffmpeg dll/dylib 随包已有先例(video 示例 release 分发)。
- **依赖**:`mng` 工具链(已有)、三平台 CI 矩阵(已有)。**验收口径**:CI 只保构建通过;安装/卸载/升级观感走真机清单(归用户,符合现行规则)。

### A2 自动更新(用户已确认;P0,依赖 A1)

- **mygo 做法**:Ed25519 签名清单(`update-<target>.json`)+ 自实现 bsdiff 增量 + 原子替换 + relaunch + native UI 更新窗口;feed 支持 GitHub Releases / S3;`-upload` 直发 draft release。
- **MoonBit 落地形态(建议两期)**:
  - **v1 全量**:检查(pr_run curl 拉清单 JSON)→ 下载临时目录 → 校验(SHA256;HTTPS 起步)→ 原子替换(posix rename;Windows 运行中 exe 走 rename swap:旧改名 + 新落位 + 重启)→ relaunch。更新窗口 UI 用本库 widget 画——「吃自己狗粮」的展示位(mygo 同款思路)。
  - **v1.5 签名**:Ed25519 验签(mooncakes 依赖待盘点,见文末;无现成绑定则 C 桩走 openssl)。
  - **v2 增量**:发布侧 diff(可先用系统 bsdiff 或自定 zstd/gzip 差分格式,不必复刻 bsdiff 的 bzip2 口径)、应用侧 patch 应用(自实现量级百行)。
  - **分工**:检查/下载/替换/重启是库能力(收 `gui/sys`/`gui/win` 一侧的 update 门面),清单生成与上传是 `mng publish` 工具侧。
- **风险**:Windows 文件占用语义、mac .app 整包替换的 quarantine/translocate 属性、Gatekeeper 与公证的联动(后置批覆盖)——真机清单项。

### A3 桌面登记面(与 A1 安装器耦合,紧随其后)

- **现状**:无深链注册、无文件关联、无 jumplist、最近文件只有读侧。
- **mygo 做法**:deeplink(自定义 scheme 注册 + 事件回调)、文件关联(Info.plist CFBundleDocumentTypes / 注册表 / desktop entry mime)、jumplist(Windows)、最近文档写侧登记、开机自启(本库已有)。
- **落地形态**:登记声明进 `mng.toml`(scheme / 扩展名列表),打包器落到各平台清单;应用侧事件回调(深链唤起走已有单实例通道转发 argv/URL)。

### A4 内建 inspector(DevTools;P1)

- **mygo 做法**:内建运行时 inspector(约 2800 行)——查看控件树、选中、编辑样式布局回灌,unix 上还能跳回编辑器改代码。
- **本库地基**:`a11y_last_frame()` 帧尾语义快照(id/父/角色/几何)已是现成的树读数面;`paint_profile_summary` 分段帧账本;uitest name 定位。
- **落地形态**:v1 只读面板(控件树浏览 + 选中高亮 + 样式/布局读数 + 帧耗时),挂 showcase 或 dev 档独立窗;v2 编辑回灌走 mngdev 样式类热更通道(能力已存在)。价值:真机排障现在只靠日志,这是第一调试器。

### A5 体积纪律与性能对比公开(P1,CI 侧便宜)

- **mygo 做法**:每次 push 测两个示例二进制体积并记账,PR 必须解释体积变化(禁 reflect.Method 系防 linker 膨胀);benchmarks 与 GPUI / egui 公开同场景对比(results.json → 官网展示),另有输入延迟、空闲内存专项。
- **落地形态**:CI 加示例体积记录与 diff(hello + showcase,超阈值红线);frame_cost_probe 已有,发版前可出对比表——**公开跨框架对比要配方法论说明**(场景、机器、轮次),可选不急;核心先立「体积不悄悄膨胀」的门禁。

### A6 CPU/GPU 像素对拍(P2,随 GPU 控件批)

- **mygo 做法**:glass 效果三份 shader + 一份 CPU 光栅孪生,测试逐像素对拍,GPU/CPU 一致是验收线。
- **本库地基**:GpuCanvas 离屏 finish 读回 BGRA 已通(三平台真机过);roadmap「无头像素快照基线」已规划(独立立项)。
- **落地形态**:同一套比对器两用——快照基线管「跨版本不漂」,对拍管「GPU 路径与纯光栅逐像素一致」;随控件级 GPU 批扩用例模板。

### A7 确定性测试时钟(P1,最便宜先做)

- **mygo 做法**:Tester 时钟静止,时间只由 `Advance(d)` 推进(期间按刷新率补帧、触发动画定时器)+ `settle()` 跑到无帧需求;动画「200ms 走 50ms 后应走四分之一」可精确断言。
- **本库地基**:uitest 已有显式 `frame()` 与 step 驱动定时器。
- **差距**:过渡动画(状态桶插值)目前只能真机看;补 `Advance(ms)`(虚拟时间整体推进)+ `settle()` 后,动画与定时类行为进无头门禁。

### A8 文档 AI 消费面(P2,便宜)

- **mygo 做法**:官网把全部文档转纯 Markdown(llms.txt)供 LLM 消费;`mygo install-skills` 给 AI agent 装技能包。
- **落地形态**:VitePress build 后处理聚合 docs/zh 与 docs 成两份 llms.txt;本仓 `.agents/skills/` 习惯已成熟,可整理一份面向下游用户的「native-gui 开发技能」随文档站发。

### A9 窗口状态记忆与会话恢复(P2)

- **现状**:无窗口位置/尺寸记忆(重启回默认);应用级崩溃恢复无模板。
- **mygo 做法**:window_state.go 记忆窗口位置尺寸;document_recovery + autosave(NSDocument 风格崩溃恢复)。
- **落地形态**:窗口状态记忆是库能力(每窗一个状态文件,`WindowHost` 收口);会话恢复归 `mng new` 脚手架模板(可选能力,不给库加复杂度)。

## B 类:路线校准建议(最终归用户)

### B1 模板与热更——方向继续,冻结的只是「HOT 覆盖面」

结论先行:模板与热更**继续做,不是砍**;建议冻结的只有一件事——HOT(热更)覆盖面的继续扩张。

- **为什么方向继续**:「让原生 DX 与 web 持平」是 2026-11-02 定的主战略,模板 + 热更是本库相对 mygo 的差异化卖点,不是追赶项——mygo 不需要热更是因为立即模式 + Go 秒级编译重启就够快;本库是 retained 树 + MoonBit,改模板重启要丢状态、回首页,热更的「亚秒 + 状态保活」(stepper 调到 7 走 HOT 后仍是 7)是真价值。模板 DX 的非热更部分(编译器、v-for、LSP、VSIX、mng new/build/dev)纯增益,照常推进。
- **为什么冻结 HOT 扩面**(三条):①成本曲线陡——热更每多覆盖一档形态,applier 复杂度上一档(状态保活、IR rev 握手、回退编排都是为此付的),v-for 含热更一律转冷已是系统在自我保护,线已到头;②上游依赖——script/真代码热换要状态迁移快照 + 运行时换码,单独立项做不完,等上游 native hot reload(roadmap「上游诉求」已列)落地后整条链降级成真代码热换、COLD 回退自动消亡,现在扩面是给将来拆的路基加荷载;③回退已是正确形态——COLD 重启自动回改动页体验已闭环,HOT 再扩一档的边际收益小于 A 类实缺口。
- **冻结线(现状即线)**:HOT = 结构 / class / 样式值 / 受限表达式(字面量、Store、运算、if、`tx`·`tr`、插值);COLD = script / v-for / 自定义组件 / children 形 / 文法外表达式。上游落地前不再把 COLD 项搬进 HOT;省下的精力转 A 类。

### B2 GPU 终态——L2 落地前先定「显示列表化」终态图

- **现状**:L1 是位图上传 + 全屏 quad(纹理合成),不是 GPU 绘制;wgpu 统一三平台,但 GTK 集成代价已实证(合成覆盖 → 自开 X 子窗承载)。
- **mygo 参照**:显示列表(scene Op 流)+ 每操作一个 instanced quad + 平台原生管线(Metal / D3D11 / GL;Linux 用 GtkGLArea 绕开 GTK 合成问题)。
- **校准点**:L2 GpuSink 协议已落,但「paint 产 Op 流 → quad 实例」的显示列表终态图未定;若不定,L1 位图上传有永居风险。wgpu 统一 vs Linux 腿 GL 直连(GtkGLArea 是 mygo 验证过的路径)值得在 L2 设计时再评估一次——不是现在改,是 L2 动手前定图。A6 对拍是这条线的验收基础设施。

### B3 测试可信度模型——无头加厚,真机瘦身

- **现状**:规则「真机归用户」,159 条用例清单 + 记录台;无头门禁是 moon test 指定包。
- **mygo 参照**:730 个测试文件 16.3 万行,headless Tester(内存渲染 + 假剪贴板/IME/拖拽 + 静止时钟)+ e2e(Xvfb / 桌面会话),视觉与交互大量自动化,真机只验「必须真机的」。
- **建议动作**:**不改规则**——加厚无头(A7 时钟 + A6 对拍 + uitest 扩面),把「布局/动画/绘制正确性」类用例沉进无头门禁,真机清单聚焦 IME / 托盘 / 通知 / 合成器 / DPI / 装机面这类真要真机的;长期看真机清单条数应下降而非增长,记录台压力随之减。

## C 类:已对齐 / 反超清单(防重复立项)

- **窗口层选型**:AppKit / Win32 / GTK3 三平台同款(mygo 同款;它 zero-cgo 靠 purego,本库编译期 C 桩,是语言生态差异不是能力差异)。
- **无障碍**:三桥同款(mac NSAccessibility / win UIA / linux AT-SPI),且「帧尾语义快照」与 mygo「每帧 AccessTree」设计撞车——两边独立收敛到同一形态。
- **IME**:TSF / NSTextInputClient / ibus+fcitx 通道一致。
- **系统工具箱广度**:传感器/蓝牙/磁盘/浏览器历史/壁纸/电源计划/夜间色温 mygo 没有,本库反超。
- **媒体**:ffmpeg 全能(软解+硬解线)vs mygo 系统解码器(AVFoundation/MF/GStreamer)零拷贝——取舍不同;硬解线落地后能力面等价,系统解码器路线可作为体积优化备选记档(与 media-decode-vendor 白名单线互补)。
- **编辑器/终端/图表/markdown/i18n/虚拟滚动/单实例/贡献入口(issue/PR 模板、双语站)**:完成度同档或反超,不立项。
