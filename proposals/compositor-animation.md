# 合成器分层动画：像素不变的动画帧由 GPU 合成

> **状态**：已规划，未动工。
> - 时间：2026-11-25 立项。
> - 前置：GPU 上屏档加固五批真机通过——本稿的上屏底座是「窗口画面经 wgpu 合成上屏」的 L1 档。
> - 起因：Windows 真机 components 观察到动画全在 CPU；现行 L1 只把最后一环（整张位图上屏）交给 GPU，控件画面每帧仍由 CPU 全部重画。回弹、变换与透明度过渡这类动画的像素内容并不变，变的只是位置与透明度，逐帧重画是纯浪费。

## 一、目标与边界

- 目标：动画帧里「像素没变，只是位置、缩放、旋转、透明度在变」的部分改由 GPU 每帧换一个变换参数重新合成，CPU 不再逐帧重画。
- 收益面：滚动惯性 / 回弹的大部分帧、transform 过渡与关键帧、opacity 过渡。
- 不碰的面：
  - 颜色、圆角、字号类过渡——每帧像素真在变，仍走 CPU 光栅。
  - 全窗 GPU 光栅化——另属「GPU 档契约线」待拍板项。
  - CPU 档行为零变化——效果分级铁律：GPU 档的观感加成必须有 CPU 档等价简化版，本线的 CPU 等价版就是现有条带快路径与直接重绘。

## 二、现状底座

- L1 上屏：CPU 位图整张上传纹理，全屏 quad 一次绘制，交换链上屏，见 `gui/win/stub.c` 的 `wm_l1_window_present`。
- 滚动条带快路径：整数位移时上一帧整块平移、只重画新露条带，见 `gui/widget/app.mbt` 的 `paint_frame` 条带分支；结构白名单在 `strip_scrollable`。
- 绘制期变换：控件级 transform 已套进光栅矩阵 CTM，脏区按变换外接矩形扩，见 `gui/widget/widget.mbt` 的 `paint_at`。
- 脏区已从宿主传到平台 present，GPU 档在脏区增量上传批之后按矩形上传。

## 三、方案骨架

**每窗的合成场景从「一张底图纹理」升级为「底图 + 若干提升层」。**

- 层：独立纹理 + 矩形 + 裁剪 + 二维变换 + 透明度，按控件树序叠加。
- 提升判据（全部满足才提升，任一不满足回退 CPU 路径）：
  - 该控件动画期间只动变换与透明度，子树内容不变。
  - 子树有界（外接矩形不超上限，内存有预算）。
  - 上方没有后画的兄弟控件与它重叠。
- 滚动层：视口内容容器提升为层，惯性帧是合成平移，新露条带做局部光栅与局部上传；回弹帧纯合成，零 CPU 绘制。
- CPU 仍是唯一事实源：提升层的内容纹理在动画开始时光栅一次，动画期间不改写；动画结束或内容变化即回收。

## 四、判据

- 底图与纯 CPU 位图逐像素一致——现有无头用例口径原样复用。
- 提升层的动画帧与 CPU 逐帧重画结果逐像素一致（容差口径与滚动横纹守卫同档：任何一行差异像素不多于 4 个）。
- PROF 新增合成行：层数、合成帧数、免光栅帧数。
- 真机：回弹与变换过渡期间 CPU 占用明显低于修复前，观感无差。

## 五、风险与开放点

- 提升的一次性光栅开销：动画开始时光栅整棵子树，若动画很短反而更贵——起拍判据要按预估动画时长门控。
- 内存上限：层数与单层面积设进程级预算，超限回退。
- 与原生子件、毛玻璃、浮层并存时的叠放语义——沿用条带白名单的排除口径。
- 无头测试与检查器截图继续走 CPU 路径，`last_frame_bitmap` 语义不变。
