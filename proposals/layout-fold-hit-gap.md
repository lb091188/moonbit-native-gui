# 列容器套折行内容的命中死区·布局层提案

## 现象·真机 2026-11-04

showcase Markdown 段：可选中文本只有顶部第一行附近能拖选，下面的块点不动。

## 根因·无头已复现

- 无头：不开真实窗口、在纯命令行环境跑布局测量来复现问题的方式。
- 内在高：内容自己算出来的高度，不依赖外部约束。
- stretch：子项被拉伸占满可用宽的档位。
- 命中测试：判断一个点位落在哪个控件上的机制。

auto 高列容器的子项主轴基准取「未约束宽的内在高」，子项最终按钦定/stretch
宽折行落地，实际比基准更高 → 容器 rect 比内容矮 → `hit_path` 要求每个
祖先矩形都包含点位 → 容器底缘以下的子项收不到指针。
  - 依据：YG3d ③ 档。
    - YG3d：本仓 yoga-mbt 内在尺寸基准的既有定案条目，记录在 experience/adaptation/common.md。

- 最小复现：`calculate_layout` 后 outer=20、inner=40、leaf=40——外层列矩形盖不住自己的子项。
  - 设置：测量叶 `f(None)=(100,20)`、`f(Some(w))=(w,40)`，双层 auto 列 + 根 FlexStart。
  - 测量叶：布局树里靠测量函数回答自身尺寸的叶子节点。
  - auto：尺寸不定、交给布局引擎按内容与约束算。
  - FlexStart：子项沿主轴起点对齐的档位。
- mdview 四块文档探针同型：最后一块 `hit_test` 全落到父列。

## 已试并撤销的修法·2026-11-04

| 修法 | 结果 |
|---|---|
| 叶子高度内在探询把宽基准传给测量函数 | 破坏 min-content 探询语义，mdview「探询档不顶高块盒」等用例红 |
| 列容器求高先收 max-content 行宽再累加子项高 | 同上族回归 |
| ③′ 基准按占用行宽现量 | 与 YG3d 定案冲突——交叉轴不定时基准取 max-content、不随可用空间漂移，专项用例钉着 |

- 判别要点：对**测量契约干净**的测量函数，③ 与 ③′ 同答，YG3d 本身无漏洞。
  - 测量契约干净：`f(None)` 的高 == `f(Some(自身 max-content 宽))` 的高。
  - 探询：布局引擎向子项询问所需尺寸的过程。
  - max-content：内容不折行时的自然宽度。
  - min-content：内容尽量折行后的最小宽度。
- 踩坑前提是存在「答案宽度与内容宽脱钩」的测量，此时行宽与折行高互相矛盾。
  - 例：mdview 正式档答 `.max(v)`，声称宽=可用宽。

## 收口进展·2026-11-05

- **mdview 侧已收口**：markdown_view 跟随容器档改 percent(100)，交叉轴确定后两趟同走定宽档——showcase 症状消除。
  - 验证：跨段选中用例钉住。
- **yoga 侧已落 ③′**：NoWrap 列且交叉宽不定时，测量趟基准按行宽现量，非 stretch 项占自己 content 宽；全量布局用例零回归。
  - 行宽：内容宽最大值被可用宽夹住。
  - 同答：与 YG3d 专项同答。
  - NoWrap：不折行、一行排到底的排布档。
- 换行列的内在路径与「容器高按子项落地高回灌」仍挂起，遇到再立项。

## 若立项的方向·二选一

1. **测量侧收口**：mdview 正式档答案宽度改答内容宽，块级铺满交给容器
   stretch——测量函数回归「答案=内容尺寸」契约，不动布局引擎。
2. **布局侧收尾**：`layout_into_impl` 尾段对内容推算尺寸的容器，按子项
   **落地后**的主轴尺寸回灌自身高。动 flex 核心，需全量布局
   用例回归 + bench，风险最高、覆盖最全。
   - 依据：CSS 语义。

## 验收判据

- 最小复现用例入 yoga-mbt 用例：双层 auto 列 + 折行测量叶，
  三层 layout 高一致。
  - 范围：契约干净版。
- mdview 多块文档：每个可选块的 `hit_test(块内任一点)` 落回自己。
- showcase Markdown 段真机：任意段落、任意行可拖选。
