native-gui 测试台

5 个应用 × 3 个平台 · 逐条记录，避免遗漏
本地存储不可用：页面跑在沙箱里（预览面板、内嵌 iframe），浏览器不允许读写 localStorage。 现在的记录只在内存，刷新或关掉就没了。两个办法：① 直接双击打开仓库里的 测试记录/index.html （localhost 或 file:// 下可正常保存）；② 先点「导出」存成 JSON，下次用「导入」接上。
通过 失败 跳过 未测 点格子直接跳到该平台 + 该应用的执行清单

怎么用

记录一条结果

选平台 → 选应用 → 在每行右侧点「通过 / 失败 / 跳过」。状态即点即存，不需要额外保存动作；失败项请补一句备注（现象、读数、报错行）。

往下滚、平台与应用选择器划出屏幕后，顶部标签栏右侧会出现「当前平台 · 当前应用 + 进度」，点它一键回到顶部重新选。

为什么带 commit

每条结果都会记下顶栏的 commit 与当前时间。只有带上 commit，才能回答「这条是哪版挂的」。切换版本前记得改一下顶栏的 commit 字段。

历史从哪来

不需要手动开一轮测试。「历史」页按「平台 + 应用 + 日期 + commit」自动聚合，把同一天同一版本内的操作汇成一次测试，失败项单列。

把失败项交给 AI 修

三个入口都能一键把失败项拼成提示词并复制到剪贴板，直接粘给 AI 对话即可：

  • 执行页右上的「失败 → AI 提示词」：当前平台 + 当前应用的失败项。
  • 总览页右上的「全部失败项 → AI 提示词」：三个平台所有失败项，按平台 + 应用分段。
  • 历史页每张卡片上的「复制为 AI 提示词」：那一次测试的失败项。

格式刻意保持简短：每个应用一段，开头两行是平台与应用，随后每条失败三行——测试点、测试条目（用例编号）、遇到的问题（即你填的备注，没写会标「（未填写）」）。

快捷键

  • 1 通过 · 2 失败 · 3 跳过 · 0 清除
  • ↓ ↑ 在用例间移动；Enter 聚焦备注
  • ⌘Z / Ctrl+Z 撤销上一步

数据存在哪

本机浏览器的 localStorage（键名 ngtt.v1），不上传任何服务器，关掉页面不丢。它绑定「这台机器的这个浏览器」，换浏览器或清站点数据会丢——所以提供了「导出」：得到的 JSON 可以放进 测试记录/ 一起提交，需要时用「导入」合并回来（按时间取新、日志去重）。

页面被嵌在沙箱 iframe 里打开时（例如某些预览面板），浏览器会拒绝 localStorage，此时页面顶部会出现黄条提示，记录只留在内存。要正常保存，请用浏览器直接打开本文件。

用例库来源

取自仓库根目录 _人工测试清单.md 的 T1a–T8h，按应用归位。清单更新后，改本文件顶部的 CASES 数组即可。

已知边界

  • 不存截图。失败项用文字备注，需要图就把文件名写进备注。
  • 只在一台机器上记录：其余平台用远程桌面 / 虚拟机操作时，用同一份页面切平台标签记录即可。
  • 浏览器禁用本地存储时（个别隐私模式），页面会提示写入失败，此时只能用导出备份。
